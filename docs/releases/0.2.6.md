ScanRelay 0.2.6 fixes the Canon imageCLASS module reporting a push as done when the printer had not taken it.

## What changed

- Canon imageCLASS module 0.2.1. A load the printer finishes but does not accept is now reported as a failed push, with the printer's own message. Before, any finished load counted as a success, so a push could say it worked while the address book stayed as it was.
- The file is now sent to the printer the way a browser sends it. The loads the printer refused were sent in a form its web server may not read. This is the likely cause, not yet proven on a printer.
- A load the printer refuses at the end because it is busy is asked again, the same as one refused at the start.
- Every Canon load writes what was asked and answered to the service log, in the Logs folder inside the data folder. It holds no passwords and no address book contents. This is the evidence for working out what a printer did with a load.
- The Kyocera ECOSYS module is unchanged (0.2.0).

## Steps for this version

Run the installer on the server as an administrator and, in its Modules step, update the Canon imageCLASS module to 0.2.1. Then push to the Canon printer again. If the push now fails, the message says what the printer answered.
