# Overnight build log

Questions that came up while building without you, and how I answered them.
Each one can be reversed; tell me which you disagree with.

| # | Question | Answer I chose | Why |
|---|----------|----------------|-----|
| 1 | Graph SDK or plain HTTP calls to Graph? The plan said the Graph SDK. | Plain HTTP calls with our own small client, and no Microsoft sign-in library. | It lets the real sign-in and Graph code run in tests against a mock Microsoft 365 that checks the certificate signature, consent and upload rules. With the SDK most of that would be untestable here. It also keeps the install much smaller. |
| 2 | Browser sign-in first, link-and-code second, for creating the app registration? | Only link-and-code and by-hand are built. Browser sign-in on the server is not. | The Microsoft client that setup borrows only allows a plain `http://localhost` return address, which a service cannot receive cleanly, and I could not verify it without a real tenant. Link-and-code works from any browser. If your tenant blocks it, use the by-hand path. |
| 3 | When is a scan moved from `Inbox` to `Store`? The spec says after Graph confirms. | The file is moved to `Store` as soon as it is finished, before upload. | Moving is how a file is claimed. A crash or restart mid-upload can then never process the same file twice; unfinished jobs resume from `Store`. Nobody opens either folder, so nothing visible changes. |
| 4 | Where do installer-owned values live (data folder, address, certificates, printer account)? The spec says no settings files. | In `install.json` in the program folder, written only by the installer. | The service can read the program folder but not write it, so these stay changeable only with administrator rights, as the spec wants. Nobody edits it by hand. |
| 5 | What counts toward the change guard limit? | The larger of: people leaving the list, or entries leaving any one printer. | An emptied group trips it, and so does emptying one printer's own group. |
| 6 | What happens to scheduled syncs while a run is waiting for approval? | They do nothing until an Admin approves or cancels. Pressing Sync now replaces the waiting run. | Otherwise the schedule would create a new stopped run and a new email every hour. |
| 7 | Can the app tell whether `Mail.Send` is restricted to the sender mailbox? | No. The health check says it cannot be seen from here and Settings shows how to add it. | The only way to test it is to send mail as another mailbox, which the app should never do. |
| 8 | FTP and SFTP scan destinations. | Modules can use them, but the app only creates the SMB share. An FTP or SFTP server pointed at `Inbox` is IT's to provide. | The spec's installer creates a share only. Adding an FTP server is a separate product decision. |
| 9 | What does "push a test entry" push, and where does a test scan go? | An entry called "ScanRelay test". Its scan shows on the Jobs page as "Test scan received" and is not uploaded anywhere. | A test should not put a file in anyone's OneDrive. |
| 10 | Alert emails go to which address of each admin? | Their sign-in name (user principal name). | It is what Graph returns without extra permissions, and in most tenants it is the mailbox address. |
| 11 | Keeping address books by hand needs the printer account's password, but the installer generates it and the spec says secrets are never shown again. | An Admin can show it under Settings, Printer account. Each time is written to the audit log. | Without it the "go live after step 2" path in the spec cannot be done. The design already assumes this password leaks, and the account can only write to the share. Secrets typed into the admin screen (printer admin sign-ins) are still never shown. |
| 12 | "When a setting changed meaning, the admin screen asks for the new value." No setting has changed meaning yet. | The mechanism is built and tested: a banner on the Dashboard and Settings listing the settings to re-check, cleared when Settings is saved. Its list is empty today. | So the first release that needs it only adds a line. |
| 13 | WiX bundle and MSI, as the plan decided, or our own setup program? | Our own setup program, `ScanRelaySetup.exe`. | **This is the biggest departure from the plan.** It asks the spec's questions, shows the summary first, does the spec's nine steps, appears under Installed apps with Modify and Uninstall, and updates in place. Because it has a silent mode, a Windows build machine installs, checks, repairs and uninstalls it on every change. With WiX I could not have tested any of it tonight. The cost: it is not an MSI, so tools that deploy MSIs cannot push it, and some organisations expect one. Wrapping it in an MSI later is possible. |
| 14 | What if the installer is pointed at a local account or share name that already exists? | It refuses, unless it made them itself. | So it can never take over or delete an account or share that belongs to something else. |
| 15 | Who can read `install.json`? | SYSTEM, Administrators, and the service (read only). | It holds the printer account's password, protected for the machine. That protection alone can be undone by any program on the server, so the file is locked down too. |
| 16 | Does Uninstall keep the data folder by default? | Yes, the box is ticked by default in the window. The silent uninstall removes it unless told to keep it. | Deleting scans and history should be a deliberate choice. |
| 17 | What does the printer account's password look like? | 32 letters and digits, with look-alike characters left out and no symbols. | Some printer address books reject symbols, and it may have to be typed by hand. |

## Decisions since

| Question | Answer | Why |
|----------|--------|-----|
| Should printer entries carry the person's email address? The spec put scan to email out of scope. | Yes, as a setting that is on by default. The address is the person's mailbox address from Entra; someone with no mailbox gets none. | The owner wants the printer's own scan to email to keep working from the same entry. The app still does not send email itself. |
| How do people reach the admin screen through a reverse proxy? | A proxy address setting. Sign-in returns to it for proxied requests, and setup adds it to the app registration. | Without it, sign-in through a proxy fails, because Entra only knew the machine name. |
